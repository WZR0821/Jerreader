# 读鼠 Jerreader

> **本 APP 通过 GPT-5.6 sol 模型开发。**

Jerreader 是一款面向中、英、日文阅读与学习的 iOS / Android 电子书阅读器。它以原文阅读为主，查词、翻译和解释按需显示，不会把译文写进原书。当前版本为 **1.5.1（build 60）**。

## 1.5.1 版本状态

目前已经打通书籍导入、书架管理、Readium 阅读、阅读内翻译、查词、生词记录和备份恢复的主要流程。iOS 与 Android 共用核心策略和文案，两端保留各自原生界面、存储方式与系统能力。

- 统一两端书架、学习页和设置页的主要布局与用词。
- 学习工具默认进入词语模式，从句子切回词语时会清理上一条句子的结果。
- 复习卡片会显示日语读音、基本形、词性、释义、活用和例句。
- “显示学习模块”可在设置中关闭；关闭只隐藏入口，不会删除生词或复习进度。
- 词典来源、第三方许可、备份范围和本机数据说明集中放在“数据与隐私”中。
- 简体中文系统的桌面显示名为“读鼠”，工程名、包名和应用内品牌仍使用 `Jerreader`。

## 主要功能

### 阅读与书架

- 支持 EPUB、PDF、DOCX 和 TXT。EPUB / PDF 由 Readium 打开，DOCX / TXT 会在本机转换为阅读副本。
- 支持阅读进度、目录、全文搜索、书签、划线批注和笔记。
- 可调整字体、字号、间距、页边距、背景、滚动方式，以及日文横排、竖排和注音显示。
- 书架支持文件夹、系列、标签、搜索、筛选和排序，并记录累计阅读时长。
- 支持按书保存完整阅读位置和排版选项；重新打开时会回到上次阅读处。
- 目录、全文搜索、书签、批注集中在阅读器导航面板中，结果可以直接跳转。
- 导入的书籍只作为不可变输入使用；翻页、翻译、批注和退出阅读都不会改写原文件。
- 重复导入时会识别已有副本，损坏文件、存储失败和受保护文件会给出明确提示。

### 翻译与查词

- 支持中文、英语和日语互译，可自动判断常见文本语言。
- 阅读时可短按查词或翻译句段，也可长按并拖动系统选区精确选择内容。
- 内置 JMdict 日语离线词典，提供基本形、假名、词性、释义、活用和例句。
- 中文词典可使用维基词典，联网失败时可退回设备上的系统词典。
- 译文只显示在临时卡片或覆盖层中；关闭卡片后正文和阅读位置保持不变。
- 配置 AI 服务后，可以对当前句子进行语法和句子结构分析。
- 翻译结果带有请求顺序保护，较早返回的结果不会覆盖用户随后选择的新内容。
- 成功结果会缓存；空结果、超时和短暂故障不会作为有效翻译长期保存。
- 日文和英文断句会处理常见缩写、引号、换行和引用助词，减少点句时选错范围。

### 学习工具

- 独立的翻译工作台支持词语和句子两种模式，默认进入词语查词。
- 生词本会保存词条、原句、查询次数和学习状态，并自动合并重复记录。
- 内置间隔复习，支持“待学习、学习中、已掌握、已忽略”状态筛选。
- 翻译收藏、生词和历史记录均保存在本机，可搜索、删除或清空。
- 支持导出 CSV、Markdown 和 Anki TSV，方便继续整理或制作卡片。
- 清空查询历史不会删除已经收藏的词条；词条详情会保留最近使用过的语境。
- 复习队列和评分算法位于共用核心中，iOS 与 Android 使用同一套状态规则。

### 数据与备份

- 阅读进度、排版设置和学习数据保存在设备本地。
- 备份可选择书籍、阅读数据、学习记录和非敏感设置，并支持手动恢复。
- 备份文件写入用户选择的目录，可设置保存天数、最多份数和容量上限。
- 恢复前会验证备份内容；重新安装后可以重新选择原目录，再从已有备份恢复。
- API Key、目录授权和可重新生成的翻译缓存不会进入备份。
- iOS 与 Android 使用各自平台的安全存储保存密钥，源码和安装包中不包含用户凭据。

## 阅读与翻译

1. 从系统文件选择器、其他 App 或文件共享目录导入书籍。
2. 点击书架封面开始阅读，再次打开时会恢复上次的位置和排版。
3. 短按正文进行查词或句段翻译；需要精确范围时，长按后拖动系统选区手柄。
4. 翻译结果可以复制、收藏或加入生词本；已配置 AI 服务时还可继续查看句子分析。
5. 目录、搜索、书签、批注和阅读设置都可以从阅读器工具栏打开。

短按翻译开启时，可以在设置中禁止同一次点按触发翻页，避免查词时误跳到下一页；滑动翻页和底部翻页按钮仍然可用。长按后的系统选区手柄始终保留，适合选择跨词或较长句段。

### PDF、DOCX 与 TXT

PDF 由 Readium 打开。带文字层的 PDF 可以点句、长按选择、搜索和批注；扫描版页面没有文字层时，可在本机按需进行 OCR。双栏论文可以按书开启双栏识别，减少左右两栏被拼成一句的情况。

DOCX 和 TXT 会先在本机生成可重排的 EPUB 阅读副本，再交给 Readium。转换只处理 App 内部副本，不会改写用户选择的原文件。当前支持 `.docx`，旧版 `.doc` 不在 App 内解析。

OCR 的结果会受图片清晰度、倾斜角度、手写内容和复杂排版影响。受 DRM 保护的出版物会被拒绝打开，Jerreader 不提供 DRM 绕过功能。

安装包请前往 [GitHub Releases](https://github.com/WZR0821/Jerreader/releases)。

## 翻译服务与隐私

Apple 系统翻译不需要 API Key。也可以在 App 内配置 GPT、Claude、Kimi、DeepSeek、Gemini、OpenAI 兼容服务或自建 HTTPS 代理。

使用在线翻译或 AI 分析时，当前选中的文字、语言方向和必要的邻近上下文会发送给所选服务商。API Key 保存在设备安全存储中，不写入书籍、日志、安装包或备份。建议为个人 Key 设置用量上限并定期轮换。

### 直接配置 AI API

1. 打开“设置 → 翻译服务”，选择“AI API（直接）”。
2. 选择服务商并粘贴自己的 API Key；常用请求地址和推荐模型会自动填写。
3. 使用“测试连接”发送固定短句，确认鉴权和返回格式正常。
4. 其他兼容 OpenAI Chat Completions 的服务，可填写完整 HTTPS 地址、模型名和 Key。

直接调用可能产生服务商费用。公开分发或多人共用时，更适合使用自建 HTTPS 代理，把上游密钥留在服务器端。代理请求包含稳定的幂等键，服务端可以据此复用短时间内的重复请求，避免重复计费。

### 本机数据边界

- 书籍、阅读位置、批注、生词和翻译历史默认只保存在设备上。
- 只有用户主动选择在线翻译、联网词典或 AI 分析时，相关文字才会发送到对应服务。
- 诊断日志不会记录 API Key；备份不会包含密钥、代理凭据和文件目录授权。
- 自动化测试使用 Mock 与本地 Stub，不访问真实翻译账户，也不依赖外网。

## 项目结构

| 目录 | 用途 |
|---|---|
| `core/` | 两端共用的阅读、选区、词典、学习和备份策略 |
| `ui/` | Android 使用的 Compose Multiplatform 界面组件 |
| `androidApp/` | Android 宿主、Room、Readium 与 ML Kit |

| `version.properties` | Android / iOS 共用的版本号来源 |

## 开发与验证

开发需要 JDK 17 和完整 Xcode。测试使用 Mock 或本地 Stub，不依赖真实 API Key。

```bash
./gradlew :core:testAndroidHostTest :androidApp:testDebugUnitTest
scripts/safe_xcodebuild.sh build
```

统一出包使用 `./scripts/release.sh`，版本号从 `version.properties` 读取。

iOS 构建统一通过 `scripts/safe_xcodebuild.sh` 执行。默认使用 generic iOS device、关闭代码签名且不启动 Simulator，以降低本机密集构建导致显示驱动异常的风险。

## 当前限制

- iOS Release 提供的是未签名 IPA，安装前需要使用者自行签名。
- Android Release 当前沿用测试分发使用的 Debug 证书，不等同于应用商店正式签名。
- Apple 系统翻译首次使用某个语言方向时，可能需要联网下载语言包。
- 在线词典、第三方 AI 服务和自建代理的可用性与费用由相应服务商决定。
- OCR 和自动断句提供的是阅读辅助，复杂版面下仍可改用系统长按选区精确选择。
