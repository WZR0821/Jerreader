# 双端流畅度修复与 UI 复验（2026-09-09）

## 改动范围

本轮处理书架封面、学习列表、生词复习和阅读成长报告中的重复计算及主线程工作。沿用 Readium 和现有持久化格式；未改动出版物导入、打开、关闭生命周期，未发布新商店版本。安全测试脚本沿用另一任务的最新修改，没有提高负载阈值。

| 问题 | 修复 |
| --- | --- |
| 复习排序的每次比较都解析 JSON，界面刷新继续重复 | 两端用不可变 `WordReviewSnapshot` 在后台一次解码并排序。定时刷新只过滤缓存状态；数据修改后重建，取消或过期任务不能回写 |
| 成长报告在视图更新时重复读取全部 JSON、展开评分并计算周边界 | 两端在后台生成七日汇总；保留评分时的书籍归属、日期边界和夏令时规则。SwiftData 模型留在主线程，仅传递 Data、日期和 ID |
| 封面在 iOS 视图刷新时同步读取；安卓重访重复解码且缩图比例固定 | 后台串行生成最长边不超过 768 像素的缩略图，24 MiB 缓存按最近使用回收；文件名、修改时间和大小组成缓存键。安卓内存紧张时清空缓存 |
| 安卓生词本与历史一次创建全部卡片，外层滚动带走搜索栏 | 改为 `LazyColumn`、稳定记录键与内容类型；搜索栏和分段导航固定，过滤结果复用，Room Flow 不随重组重复创建 |
| 语法列表逐行扫描整份书架 | 两端预先建立书籍 ID 集合，复用当次过滤结果 |

缓存只读独立封面文件；不会改写书籍内容和修改时间。封面内存上限指缓存保留量，当前显示的图片和解码临时内存不包含在内。复习和成长快照仍与本机记录量成正比，未引入数据库分页。

## UI 对齐

- 生词本/历史搜索框统一最小高度 48、左右内边距 12；控制栏左右留白 20、上下 10、间距 10，使用相同实色背景。iOS 去掉该区域的实时模糊。
- 安卓列表匹配原生字号层级：词头 20、正文与分组标题 17、读音/次级内容 15、附注 12；搜索文字 17。保留系统字体缩放。
- 安卓空列表改为剩余内容区域内居中；长列表内容滚动、导航和搜索保持固定。
- 设备测试发现搜索提示只出现在画面，未暴露为无障碍名称；补齐搜索框、导出、收藏和删除按钮的名称与按钮语义。Debug 数据夹具改用真实 BCP-47 语言标签，避免截图出现 `JAPANESE` 等内部枚举名。
- 五个工具继续使用既有的 16 内边距、12 子项间距、0.75 边线和至少 44 的按钮高度。
