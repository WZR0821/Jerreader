# Jerreader 阶段总结与开发维护方案

日期：2026-10-05。范围：iOS、Android 同等优先的现有功能维护。本文根据当前源码、唯一可见的发行提交及仓库中的阶段记录整理；历史测试不能自动视为当前工作区通过。

## 1. 当前判断

Jerreader 已经走过“能导入、能阅读、能翻译”的原型阶段，具备完整的本地阅读与学习主流程。当前最需要的是把已有能力做稳、把验收证据补齐，再扩大范围。

- 两端源码版本仍为 **1.3.5 / build 56**；Git 可见发行提交为 `b2ae39b`（2026-08-09）。9 月至本轮有大量尚未发布、尚未提交的工作区改动，不能把所有源码能力直接视为已交付给用户的版本。
- iOS 使用 SwiftUI、SwiftData、Readium Swift；Android 使用 Compose、Room、Readium Kotlin，`shared` 承载部分规则和界面组件。iOS 当前没有直接使用 Kotlin 共享框架。
- 保持原文、保留阅读位置、及时响应、错误可恢复，是后续维护的优先目标。
- 本轮不变更版本号或发布安装包，不调整出版物导入、Readium 打开/关闭生命周期、数据库 Schema 或备份格式。

## 3. 本轮实际优化

### iOS

1. 翻译工作台的附属词典查询原先没有独立截止时间。现在复用现有 watchdog，以 15 秒独立期限退出等待；输入变化、关闭页面或重试都会取消旧任务，迟到结果受任务取消和请求 ID 双重保护。
2. 补充词典详情时显示进度指示；超时或失败后提供“重试词典查询”。重试只查询词典，保留已有译文，不重新调用翻译服务。词语模式的加载文案同时覆盖本地查词与翻译准备。
3. 英语离线词库原先每次查询打开数据库、准备 SQL，再关闭；多个候选词会重复此过程。现在由词典 actor 保管一个只读连接和预编译查询，一次按原顺序查询、去重候选。成功替换或删除词库后释放旧连接，下一次读取新版本；安装失败保留原连接与词库。
4. 查词页说明改为实际的“本地优先、未命中再联网”，避免让用户误以为离线功能不可用。取消本地查询后也不会继续启动网络后备服务。

### Android

1. 将独立翻译页的词典补全提取为 `StandaloneWordLookupSession`，与主翻译任务分开管理；继续使用既有的 15 秒超时与取消保护。
2. 增加词典补全进度与独立重试。查词超时不清掉译文；历史写入失败时保留释义，重试优先保存已有结果。页面输入、语言、模式或服务变化会一起使词典任务失效。
3. 本地词典已给出译文时，直接复用同一词语、同一语言、含有效释义的结果完成补全，不再次调用查词链路。不匹配的旧释义不能复用。
4. 在离线、内置、联网三级查词交接前后检查取消状态。即使上一服务忽略取消，用户已取消的请求也不会继续启动下一服务或返回过期结果。

### 验证工具

保护脚本此前只排除“通过数＋跳过数大于总数”，因此部分未结算报告也可能被认成通过。现在要求至少一项通过、零失败，且“通过数＋跳过数等于总数”。新增缺项及总数不一致回归。负载上限 50、单 job、构建互斥和模拟器授权规则保持不变。

## 5. 后续开发顺序

每次只选下面一个里程碑实施，完成验收后再进入下一步。人日为安排顺序的参考，实际取决于设备与缺陷数量。

| 优先级 / 建议阶段 | 工作内容 | 完成标准 |
| --- | --- | --- |
| P0：稳定候选版，先做 | 整理现有工作区，按阅读、学习、数据、工具拆分可审查提交；建立当前需求与验收清单；保留发行版本和更新说明 | 任一候选版能对应到代码提交、版本、测试日志和已知问题，旧安装包不冒充新构建 |
| P0：数据与核心阅读验收 | 在稳定真机或另一台稳定 Mac 上验证升级、备份恢复、导入去重、阅读位置、取消/超时、退出重开 | 至少 5 本有合法使用权的 EPUB 覆盖横排、竖排、ruby、图片和目录；源文件与书架副本 SHA-256、修改时间均不变；书籍、收藏、笔记和进度不丢失 |
| P1：两端 UI 与流畅度专项 | 使用同一组样本检查小屏、大字号、深色、横屏、长释义/长译文；记录冷/热打开、缓存查词、长列表滚动 | 同一操作语义一致；没有被裁掉的主要按钮；返回后位置不丢；数据集、设备、系统、采样次数和结果可复现 |
| P1：分模块维护 | 逐次抽出阅读翻译请求、选区布局、导航和记录保存；把纯规则从巨型 ViewModel/View 中移出 | 每次一个边界，保留行为与回归；UI 仍依赖领域协议，网络服务仍有 Mock，数据对象不跨线程传递 |
| P2：学习闭环改进 | 先观察“阅读→收藏→复习→回原句”的阻力，处理已存在功能的入口、筛选和恢复体验 | 真实用户能从错词回到原句，复习评分不会改变历史书籍归属；再决定是否立项新能力 |

当前阅读主文件约为：iOS `EPUBReaderViewModel` 2,634 行、`ReaderModels` 3,775 行；Android `ReaderActivity` 2,097 行、`LearningScreen` 约 1,240 行。体积说明维护成本正在上升，但不宜为缩短文件而同时重写两端。此次 Android 词典补全的独立会话可以作为逐步拆分的方式。

登录、云同步、支付、整本翻译、扩展格式与恢复语音功能都需另行定义需求和验收，不能从这份维护方案自动推导出实施授权。

## 6. 可执行的日常维护制度

### 每次修改

1. 先读 PRD、架构、AGENTS 与最近验收记录，明确修改范围和用户可见行为。
2. 将问题写成可复现步骤：平台、版本、设备、输入、预期、实际结果；日志不记录 API Key 或完整书籍正文。
3. 对取消、数据持久化、缓存身份和迁移等高影响逻辑补离线回归；简单文案不添加镜像测试。
4. 串行进行资源预检、相关回归、当次唯一构建。失败先分析错误，不循环重跑或更换缓存重试。
5. 记录本次修改和实际通过项目；未执行或安全中止要单列。设备截图须对应本次代码。

### 每个发布候选版

- 核对两端显示版本、内部构建号、代码提交和交付文件摘要；正式发布包的版本管理独立于本次维护，不覆盖用户高版本测试环境。
- 使用上一个发行版数据验证 SwiftData / Room 升级，另做新安装与备份恢复。先备份，不用删除数据库掩盖迁移失败。
- 使用 Mock 完成阅读/翻译/查词路径，再在用户可控的真实账号和设备上核验平台翻译与 API；这两类结果分别记录。
- 验证低存储、无网络、下载取消、权限失效和 App 切后台。恢复失败必须保留原数据，不仅检查成功路径。
- 若改动导入或 Readium 开关生命周期，必须运行书籍内容与修改时间不变正式回归。主机测试不能替代它。
- 设备测试中出现显示卡顿、黑屏或系统无响应，立即停止并保留现场；转移到稳定设备，不提高阈值重试。

### 每月或一个维护周期

- 按崩溃/数据、阅读阻断、性能、UI、功能建议排序问题；先处理前两类。
- 清理失效说明和重复实现，核对服务模型目录、词典来源/许可、依赖固定版本；依赖升级单列任务，不与大功能混做。
- 复核合成 EPUB 夹具、离线 Mock、迁移数据和备份恢复用例可用性。真实用户书籍和密钥留在仓库外。

### 性能记录模板

| 指标 | 样本与测法 | 报告要求 |
| --- | --- | --- |
| 阅读器打开 | 固定 5 本样书，冷/热打开各重复采样 | 中位数及较慢样本、书籍大小与排版、设备/系统；不含首次联网依赖下载 |
| 查词 | 本地命中、缓存命中、未命中、超时各自采样 | 展示释义耗时与主线程卡顿分别记录；网络耗时不混入本地优化结果 |
| 学习列表 | 1,000 条记录，搜索、滚动、进入详情再返回 | 不重复解码/请求，交互仍可响应；真机测量后再设具体预算 |
| 内存 | 大书打开/关闭、连续切换封面和词典 | 区分系统缓存与持续增长；记录多次往返后的趋势 |

本轮词库微基准只说明数据库连接复用开销，不外推为整机速度提升比例。

## 10. 同日后续：个人签名安装失败定位

用户提供爱思助手重签后的 IPA 和“无法安装，因为无法验证其完整性”截图。对已签名文件的检查确认：ZIP 完整，主程序包含现代代码签名及 DER 权限；签名证书包含于描述文件，应用标识、签名权限和已配对 iPhone 的设备标识匹配，证书及七天个人描述文件均在有效期内。在非云同步临时目录解包后，`codesign --verify --deep --strict` 通过。云同步工作目录解包时自动附加的 Finder 元数据不作为原 IPA 的问题判定。

重签包的主程序 ZIP 权限由 0755 变为 0644。生成保留全部文件内容和签名、仅恢复执行权限的诊断副本后，严格验签仍通过。随后在用户已连接的 iOS 27.2 真机进行一次系统安装，获取明确拒绝原因：`MIInstallerErrorDomain / 13`、`LibMISErrorNumber = -402620383`（`0xe8008021`），即 **免费开发者签名 App 安装数量已达上限**。系统列出三个现有名额占用，Jerreader 没有安装成功；恢复权限并未解除这个限制。

此次已定位到安装授权数量限制，不能据此声称 App 已通过真机运行验收。没有删除其他应用、撤销证书或改动业务源码。后续安装需用户自行腾出一个免费个人签名名额，或提供适用的付费开发者签名；卸载其他 App 必须先得到用户对具体应用的授权。诊断副本保留在忽略目录，不作为已解决问题的新版本交付。
