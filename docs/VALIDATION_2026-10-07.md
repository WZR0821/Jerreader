## 性能测量边界

通过完整设备套件时的 32 MiB 文件试验：旧流程三次耗时为 1618、1441、1522 ms，新流程为 380、364、373 ms。中位数 1522 → 373 ms，减少约 75.5%。该用例交替执行新旧流程，保留 fsync 与完整 SHA-256 校验，并验证源文件内容及修改时间。原始值来自 `20261007-021501-h_mjpuv1` 的 `file-io-benchmark.txt`。设备为 Android 15 / API 35、1080 × 2280、440 dpi、两个虚拟核心、软件渲染；请求内存 2048 MiB，SDK 实际 guest MemTotal 为 2,532,900 KiB。

这只衡量拷贝、指纹与校验的文件环节，不是完整 EPUB 导入、首次 Readium 位置索引或真机翻页速度。

Swift 主机微基准另测词典连接复用及学习答案快照：500 次 SQLite 查询 0.2782 → 0.0213 秒；600 条学习记录、20 次回答 1.2727 → 0.0647 秒。它们属于主机逻辑测量，不能转换为手机整体提速比例。

- Android UI 验收入口在 instrumentation 连接前设置系统字体，每个已审核 UI 用例在新进程中执行一次，严格串行；逐份及汇总报告都必须结算成功，无失败、跳过或漏跑。该执行流程在 Android 15 完整套件中通过，不能推定它已经解决 Android 16 的 System UI 故障。
- `20261007-015637-_2jsb11b` 的完整 events/logcat 显示 Play 商店镜像在任何 UI 用例开始前已有电话与 System UI ANR、蓝牙 SIGABRT，instrumentation 随后启动失败，没有完成用例。主机资源稳定不能代替 guest 健康；入口增加开机 ANR 检查，使用已有轻量 AOSP 镜像并关闭 guest Vulkan，后续结果另记。关闭 Vulkan 是[官方提供的排障选项](https://developer.android.com/studio/run/emulator-troubleshooting)，尚不能由此断言根因就是 Vulkan。
- `20261007-020757-rs2fno1p` 的 Android 16 AOSP 同样出现开机 ANR，启动检查已阻止执行用例。随后建立独立 Android 15 AOSP 测试设备，在开机完成后先等待资源稳定，再安装 APK/设置网络，正式 12 项套件通过。不能据 Android 15 的成功声称 Android 16 镜像故障已解决。
- 新 IPA 打包器只接受成功的安全入口 Release 构建，检查 iPhoneOS / arm64、未签名、无描述文件、无测试资源、ZIP 权限与内容摘要。

## 本轮结算与问题定位

本轮已完成构建、离线基础/文件设备回归、两端 UI 对照以及未签名 IPA 校验。Android 功能与文件回归沿用完整 12 项套件中的 8 项通过结果，随后改动仅涉及界面和测试脚本；当前四项 UI 在 `20261007-174203-o_h02g_1` 完整通过。四项实际用例耗时依次为 28.343、23.208、23.910、20.268 秒，不含开机与资源稳定等待。测试设备在结束时由入口清理。

## 后续开发维护方案

1. 修改导入和阅读器生命周期时，先保留内容与 mtime 回归，再优化 IO；完整哈希不能替换为仅检查文件大小或时间。
2. 每次界面修改保存同页、同状态的两端截图，至少覆盖浅色、空状态和深色大字；区分应用布局与系统字体、安全区域、系统选择器等平台差异。
3. 词库按固定来源和哈希生成，复查常用词、屈折索引、未知词和许可；模型下载、删除与推理仍经协议和串行适配器。
4. 先验证 APK/IPA 再交付；在报告中分开编译、单测、设备验收、签名安装和真机性能，不把未执行的阶段记为通过。
5. 下一轮真机覆盖：已下载后断网重启、下载中断恢复、无 Google 服务 Android、大 EPUB 首次/再次打开。记录设备、系统、文件大小、冷/热条件、三次原始值及中位数。
