# 中日学习与两端 UI 校验

## 本轮改动

- 翻译页增加“日语 → 中文”“中文 → 日语”快捷入口，保留原设置及英语方向。显式选择日语可避免纯汉字词被自动判为中文。
- 两端内置同一份 128 条中日基础词汇（`shared/dictionaries/ja-zh-core.tsv`，v1，6,755 字节）。日语表记、假名、已有活用候选返回中文释义；中文以明确别名反查日语。词语模式命中后无需启动在线翻译或下载系统语言包。未收录内容仍使用原服务；这不是完整日语词典。
- 离线页面将中日基础词库和本机练习放在前面，英语 ECDICT 保留为可选扩展。
- 学习工具改为独立页面标题与返回导航；安卓进入工具时不再保留主页面的三个分栏。原句自测返回时先回原句列表。
- 统一五个工具页的 16 点边距、16 点圆角卡片与 720 点宽度上限。长列表使用懒加载，避免安卓一次组合全部收藏。
- 语法编辑均包含标题、语言、标签、原句和解释。安卓阅读器改为先显示编辑页再保存。搜索无结果、无可用书籍位置均有提示，删除按钮使用破坏性操作颜色。

### iOS 环境事件

按用户本轮 UI 校验要求，通过 `scripts/safe_xcodebuild.sh ui-test` 指定一个 iPhone 16 / iOS 18.2 模拟器、2 个构建 job、禁用并行测试。首次编译发现 UI 样例缺少 `usageNote` 参数，定位修正后进行下一阶段验证。

第二次编译完成后，模拟器启动使 1 分钟系统负载升至约 134.94（8 逻辑核心，构建保护阈值 16），系统查询发生延迟。立即向本次 xcodebuild 发送中断，只关闭所指定的模拟器；未关闭其他设备、未清空模拟器、未操作 WindowServer，且本轮不再重试 iOS 模拟器。

日志：`.build/zh-ja-ui-ios.log`（测试样例参数编译错误）、`.build/zh-ja-ui-ios-validated.log`（`TEST INTERRUPTED`）。这遵循 [AGENTS.md](../AGENTS.md) 的“立即停止当前验证，不得继续重试”规则。**目前不能宣称两端动态页面或截图已通过一致性验收。**

## 截图发现并修复的问题

- 浅色模式底部三键导航图标过浅，深色模式状态栏仍为暗色图标。新增 `JerreaderSystemBars`，跟随应用颜色设置系统图标和背景；API 23–25 使用能衬托白色导航键的深色背景。
- Room 数据库观察流与软件渲染存在异步帧，首批部分截图早于真实数据展示。UI 用例增加数据断言与画面稳定等待，不把暂态空白截图当成最终页面。
- 新增中文反查用例最初未读到结果；增加输入状态确认和画面就绪等待后，单独运行与完整套件均通过，没有为该断言失败改动生产查询逻辑。最终截图可见“食べる → 吃”和“阅读 → 読む（よむ）”。
- 中日反查产生带读音的结果后，方向互换仍可命中原日语词条，避免不必要的在线回退；两端新增一致回归。

## 可复用的验收用例

- iOS：`JerreaderLearningUITests`，独立内存 SwiftData，覆盖中日复习、自测答案、语法编辑、五个页面空状态与大字深色状态。
- Android：`LearningUiParityTest`，不可导出的 Debug Activity 与内存 Room，渲染真实 LearningScreen 及工具页；覆盖同一组中文文案与日文学习样例。
- 安全脚本允许按目标筛选最多 8 个测试类/方法，仍维持单 destination、非并行、2 job 和签名禁用。筛选不接受任意命令参数。

## 保留的正式验收目标

- 在安全的 iOS 设备环境补跑本轮 UI 用例，再与安卓截图对照；此轮仅完成 iOS 源码层面的布局核对与编译。
- 在 iOS 设备运行出版物内容与修改时间不变、SwiftData V1→V2 以及新旧备份兼容回归。
- 日语离线词库扩展需进一步验证来源许可、中文覆盖和活用命中；当前不冒充大型词典。
- 书内短按查词的正式目标不因本轮新学习页验收而视为完成；iOS 仍保留长按选词/翻译卡加入生词本的已记录降级路径。
