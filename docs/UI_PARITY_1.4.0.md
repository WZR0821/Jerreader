# Jerreader 1.4.0 双端界面验收

本轮处理主界面、二级界面、学习流程和图标的一致性。iOS 和 Android 的营销版本统一为 1.4.0，内部版本统一为 58，作者显示为 Jerry Wong。以下记录本轮实际测试证据；历史 1.3.x 的通过记录不代替本轮验证。

## 实施范围

- 学习默认进入「练习」，保留「翻译 / 生词本 / 历史」。练习页直接展示已有词语、原句收藏数量，并可进入复习、原句、语法、成长报告和离线词典；数据仍使用现有数据库，不新增另一套学习记录。
- 两端常用图标由 `design/jerreader-icons.json` 的原始矢量路径生成。`scripts/generate_ui_icons.py --check` 检查 Swift / Kotlin 产物是否同步，避免独立绘制产生差异。
- 安卓主导航及学习、设置二级页使用一致的返回栏；设置二级页保留底部导航。系统返回与页内返回都先退出原句自测，再返回学习首页。
- 安卓主题、排版、翻译、隐私、操作指南及备份页改用同一套表单间距、分组和控件；备份按 iOS 的「位置 → 自动备份 → 策略 → 范围 → 手动备份 → 恢复」排序。现有备份服务和文件处理代码保持原有实现。
- 两端语法收藏增加删除确认；取消后保留收藏。
- 翻译草稿在切换练习、生词本、历史以及底部主导航后保留；只保留输入与语言/模式选择，不自动重发请求。安卓的返回处理只作用于当前显示的导航栈。
- 非空书架将统计移至书籍下方，统一 2:3 封面、书籍信息布局、文件夹入口和搜索空态；书籍编辑改为带取消/保存的分组表单。
- 阅读字号在安卓以「号」显示，与 iOS 使用 17 号基准；内部仍存储现有比例，不迁移书籍数据。
- 截图复查后，两端学习主导航固定为紧凑标题，切换分区不再在大标题和行内标题之间跳动。安卓说明文字按对应页面统一字号，设置选项使用强调色。
- 小封面按同一尺寸基准缩放整幅图案，修复编辑页预览裁切书名。iOS 原生菜单直接使用 `Label<Text, Image>`，修复自定义标签封装导致的空白菜单；书架分区与统计图标也使用共同矢量。

## 阶段总结与后续维护安排

| 阶段 | 结果与维护重点 |
| --- | --- |
| 基础能力 | 沿用 Readium 阅读、SwiftData / Room 持久化及服务协议；不把译文写入书籍。 |
| 安卓离线与读取 | 内置基础词典、显式管理可选本机模型；文件流式复制同步摘要，保留内容与修改时间检查。速度结论限定到实际测量的环节。 |
| 1.4.0 共同界面 | 51 个原始矢量图标统一生成，学习与设置导航、书架、表单和草稿状态对齐；以最新截图和操作结果验收。 |
| 发版 | 版本、签名身份、覆盖安装、实际启动及归档校验需要各自留下证据，不能只依据编译成功。 |

- 每次界面修改：更新两端对应页面，检查正常、空数据、深色大字及返回路径；草稿、取消删除、取消编辑必须保留原数据。
- 每次导入或阅读生命周期修改：运行原书内容与修改时间不变回归；文件微基准与阅读器完整打开耗时分开记录。
- 每次发布：验证双端版本号，保留可回退的已签名 APK 与未签名 IPA、SHA-256、测试日志和截图；安卓检查同一签名升级，iOS 个人证书重签安装另做真机验证。
- 依赖维护：集中评估 Lint 的版本提示，升级单个依赖后运行对应回归；不在打包尾声批量升级阅读内核或数据库库。

## 比较方法

同一套离线测试数据、同一页状态逐项截图：默认、空数据、深色大字号，以及主题、阅读排版、翻译、指南、备份和隐私二级页。保留原始截图、测试日志和对应安装包校验值。系统状态栏、导航手势区域、字体栅格化，以及系统文件选择器属于平台差异，不作为应用内容像素一致的证明。

## 后续维护

1. 图标只修改 JSON 源，再生成两个原生产物；不要单独编辑生成文件。
2. 新页面先给出双端共同的标题、分组、操作顺序、空态和错误态，再实现平台组件。
3. 每次学习或设置布局变化，运行正常/空态/深色大字与二级页面测试；截图要来自最终代码，不沿用历史包。
4. 保留 iOS 的系统文件授权、Android 的 SAF 和平台密钥存储；说明文案应准确，不为追求相同文案而误述行为。
5. 涉及导入或阅读器生命周期时，另行运行内容与修改时间不变的正式回归；视觉测试不能替代它。
6. 默认仍通过共享队列执行。2026-10-12 用户要求本轮忽略外部占用，相关例外只用于已获授权的命令，本任务内部继续串行，不改变后续任务默认保护。

iOS 的 5 组 UI 场景来自上表中各场景的最后一次通过记录，并非一次调用全部通过。初次运行发现原生书架菜单空白，改为直接使用 `Label<Text, Image>` 后恢复；随后发现学习分区切换留下键盘，已在切换和页面退出时清理焦点，复验同时断言草稿保留、键盘关闭。旧失败日志保留用于定位，不计为通过。

最终逐图检查还发现深色练习页截图捕获了切换动画中间帧。测试现在先确认所选分区与目标内容，再等待连续稳定画面后保存图片；该修正只在 UI 测试中，不改发布 App。补验两组均通过，最终图集已替换为稳定画面。

iOS 跳过的 3 项需要额外真实 EPUB / ruby 文件，当前未提供；内置 fixture 的导入、Readium 打开与关闭后内容、mtime 不变测试通过。安卓的 Readium 打开/关闭不变性、无模型和无 API 的基础词典测试也通过。平台真实翻译模型下载、iOS 个人证书重签安装仍需真机验证。

### 读取性能结果

32 MiB 文件复制、指纹及完整性检查微基准：旧流程 `[2176, 1493, 1469]` ms，新流程 `[383, 374, 362]` ms，中位数 **1493 → 374 ms，耗时减少约 75%**。原始数据位于安卓完整设备日志的 `screenshots/file-io-benchmark.txt`。这是模拟器上该处理环节的测量，不能换算成所有书籍或真机的整书打开提速率。

### 保留的平台差异

- 系统状态栏、底部手势区、字体、原生文件/照片选择器保持平台行为。
- 安卓更换封面仍从书架更多菜单进入；iOS 在书籍编辑 Sheet 中选择照片，不能声称这一操作已完全一致。
- Apple Translation 与 Android 本机语言模型的管理界面、系统备份文件授权和既有备份默认策略保留平台差异，不为截图相同而改变数据策略。
- 阅读排版保留两端引擎已有选项差异：iOS 提供分边页边距设置，Android 提供原书 / 横排 / 竖排三种方向。帮助说明随平台实际操作编写，行数与部分控件尺寸存在差异。
- 本轮覆盖的主要页面已对照检查；未测机型、尺寸和真实书籍不计入验收结论。
