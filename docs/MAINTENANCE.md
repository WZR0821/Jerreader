Jerreader 是一款面向中、英、日阅读与学习的 iOS 和 Android 电子书阅读器。它支持 EPUB、PDF、DOCX 和 TXT，以原文阅读为主，查词和简体中文翻译按需显示，不把译文插入原文。

## 当前源码：双端 2.0.0（72）

当前版本已经完成导入、书架、实际 EPUB 阅读、阅读内翻译和学习记录主流程：

- iOS 18+ SwiftUI 工程，同时支持 iPhone、iPad 和横屏。
- 2.0.0 起书架、阅读器、学习和设置统一使用「纸墨」设计规范（[DESIGN_2.0.md](DESIGN_2.0.md)）：暖白纸面、墨色文字，强调色只用在主要操作、选中状态和进度上；底色 → 纸卡 → 浮起元素三级层次（浅色用染色阴影，深色改用描边）；按压、状态切换、选择、首次出现、主卡共用一套弹簧参数，两端数值相同，系统“减弱动态效果”（Android 为“移除动画”）打开时一律换成 0.18 秒交叉淡化。
- Readium Swift Toolkit 固定到上游提交 `3d8bcdc`（基于 3.8.0，包含切换 CSS 阅读偏好时清理已缓存 HTML 的修复）。
- `TranslationService`、`LexicalLookupService` 协议，以及暂时保留但不向界面开放的 `SpeechService` 内部边界。
- Apple Translation 系统翻译、AI 大模型（用自己的 Key 直连 Claude、ChatGPT、DeepSeek、通义千问、豆包、Kimi、智谱、MiniMax、Gemini 或自定义服务）、AI 套餐（2.0.0 起：用 ChatGPT 账号登录后走订阅额度的“ChatGPT 套餐（实验）”，以及说明 Claude Max / Ultra 附带 API 额度用法的“Claude 套餐额度”；实现见 [架构说明](ARCHITECTURE.md) 的「2.0.0 AI 套餐与「纸墨」界面」一节）、AI 代理（经自建 HTTPS 后端转发）、翻译缓存、失败重试与备用服务、中文维基词典真实查词和 iOS 系统词典后备。
- “学习 → 翻译”采用独立的翻译工作台：原文可自动识别或手动选择中文、英语、日语，译文可选择中/英/日，支持词语与句子模式，并可在当前页面单独选择 Apple 系统翻译、AI 大模型或 AI 代理；这些选择不会暗中改动阅读器的全局翻译设置。
- 语音、听书、发音按钮和语速设置仍统一关闭；唯一例外是单词复习卡对日语词提供"朗读单词"和"朗读原句·跟读"（iOS 由 `SpeechFeatureAvailability.learningReviewIsEnabled` 单独打开）。底层实现由功能开关隔离，未删除或改动共用的选区、翻译和学习数据逻辑。
- 完整的离线回归测试和架构说明。
- 设置中的“备份中心”支持选择 iCloud Drive、“我的 iPhone”或其他文件提供商中的文件夹，并对该目录保存可跨启动解析的访问书签。书籍、阅读、学习和非敏感设置四类范围均可选择；自动和手动备份写入当前文件夹，并按保存天数、最多份数和总容量从最旧文件开始清理。重装后重新选择同一文件夹即可在列表中点“恢复”；每次手动恢复都会创建新的系统文件选择会话，并兼容 iCloud/File Provider 将未下载备份暂时报成动态通用文件类型的情况。文件选择阶段的兼容不会放宽恢复校验。目录授权、API Key、代理凭据和可再生翻译缓存不进入备份。
- 从“文件”、iCloud Drive、其他 App 的打开菜单或 AirDrop 导入 EPUB、PDF、DOCX 和 TXT；在书架里导入时可先选格式（全部、EPUB、PDF、Word、TXT），选定某种格式后系统文件选择器只能选这种格式；系统先交给Jerreader一个导入副本，Jerreader不原地打开或写回原文件；App 沙盒内的出版物副本也以只读权限交给 Readium，并在整个阅读会话及最终关闭后持续保持原修改时间。选中文档后会直接进入阅读页，已导入的重复文件会打开书架中的现有副本且不会再次读取源文件。
- 支持通过 Finder 或 Windows Apple Devices 将上述文件复制到 App 的文件共享目录。
- EPUB 和 PDF 由 Readium 校验并打开；DOCX 和 TXT 在本机转换为标准的可重排 EPUB 副本后再交给 Readium，原文件不会被修改。
- 将阅读副本和封面保存在 App 沙盒，并用 SwiftData 持久化书架。
- 重复文件、损坏文件、受保护文件和存储失败提示。
- 点击封面全屏进入 Readium Navigator。iPhone 保持逐屏阅读；iPad 与横屏由 Readium 按可用宽度自动选择单页或双页展开，超出当前版面的内容进入下一页。
- 书籍打开超过 25 秒会自动退出加载状态并显示“重新打开”，过期打开结果不会覆盖后续重试；书架的最近打开时间只按“刚刚 / 分钟 / 小时 / 天”显示，不再逐秒倒数。
- 逐屏模式禁止纵向漂移、回弹和缩放；左右边缘点按、横向轻扫和大尺寸底部按钮都只前进或后退一个屏幕页，不跳整章。
- 阅读设置包含字体、0.5 号步进的字号、行间距、段间距、页边距、预设/自定义背景、逐页/滚动模式、进度显示和日文版式；每本书可独立保存，App 设置也可统一指定新导入书籍的初始排版，并通过“一次应用”或持续同步开关应用到现有全部书籍。
- 阅读界面有「标准」「沉浸」两种布局，在 阅读设置 → 阅读界面 → 界面布局 切换，对所有书生效：标准时上下栏常驻，正文排在两栏之间；沉浸时正文全屏，上下栏默认收起，轻点正文上下的空白处呼出，4 秒后自动收起。
- 中文、英文、日文互译。日文书可在“原版 / 横排”之间切换：原版保留 EPUB 的横竖排与方向，横排则同时强制章节间与章节内都按从左向右逐页阅读。
- 按书保存并恢复完整 Readium Locator 与排版选项。
- 阅读器内的目录、全文搜索和书签集中在同一导航面板；EPUB 使用 Readium 全文搜索，PDF 搜索文字层，结果与书签均可直接跳转。
- 选中文本后可保存划线、批注和笔记，并可选择标记颜色。EPUB 使用独立 Readium Decoration，PDF 保存页码与归一化页内坐标；标记不会写回原书，可从阅读导航面板查看、跳转、编辑或删除。
- 按书统计进度与累计阅读时长；书架支持类似文件夹的分组、系列、标签、最近阅读、搜索、筛选和 SHA-256 重复文件检测。可编辑封面、书名、作者、语言、系列和标签，也可批量修改文件夹、系列、语言及标签。
- 阅读内翻译采用三层交互：短按正文可在“句子 / 段落”间选择，一次只识别并翻译所在句或所在段；长按初始选区智能补全单词或句子；继续拖动系统选区手柄后切换为精确模式，严格翻译用户最终框选的文字。设置默认开启“轻点翻译时禁用点按翻页”，同一次触摸不会同时翻译和翻页；滑动翻页始终保留，关闭轻点模式后左右点按翻页自动恢复，此时 EPUB 中轻点词语会直接打开语境查词并写入学习记录，轻点空白处仍切换阅读界面。
- 英文点句与长按扩句共用同一断句器；在系统语言分词上校正人名首字母、缩写、小数、引号和 EPUB 源文中的换行，避免把 `J. K. Rowling`、`U.S.` 或 `3.14` 误切。日文断句会修复 `「本当？」と彼は……`、`『危ない！』って彼女は……` 这类引号内终止符后的引用助词边界，同时不吞并真正独立的下一句。
- 智能选区稳定 170ms、精确选区稳定 280ms 后才发起请求；按“书籍章节＋规范化文本＋语言与服务配置”去重，同一内容正在翻译或已有结果时不重复请求。选区位置更新与翻译请求分离，拖动原生选区手柄不会因为 frame 抖动额外调用翻译服务。
- Apple 翻译引入分阶段 watchdog：未能启动的 `TranslationSession` 只自动重启一次；进入系统 session 后保留 180 秒语言准备预算，网络翻译为 30 秒。独立翻译页的附属词典查询另有 15 秒期限，失败可单独重试；超时后的迟到结果不会覆盖当前状态。阅读器成功与失败卡片都可手动“重新翻译”，同一段文本 5 秒内只允许一次手动重试，加载中不会并发重复请求。
- 翻译服务返回的空字符串、零宽字符或其他不可见 Unicode 不会再进入成功界面；旧缓存中的空白结果会被自动清除并重新请求，短暂故障仍可自动重试并切换已配置的备用服务。成功卡片使用确定性可见高度与内部滚动，不再由自适应分支偶发生成空白内容区。
- 段落译文框与完整原文选区保留安全距离，但框内只按实际译文高度展开，不再为段落模式强行填满上限而留下大片空白；较长译文达到舒适高度上限后才在卡内上下滚动。原版竖排时优先将卡片收窄到可读宽度并放到文字列左侧或右侧，不再固定挤在页底。
- 中/英/日文本优先自动识别，不只依赖 EPUB 语言元数据；Readium 页面保留可见 ruby 注音。选区链路不再监听触摸或改写 WebKit 的原生 Range：`rt/rp` 仅对命中和独立选择透明，长按由下方汉字基文接收，原生手柄始终归 Readium/WebKit 管理。语义层只读当前 DOM Range 并排除注音；对旧 WebKit 仍回传的纯 `rt` 选区，会映射回对应的汉字节点。可见高亮使用不接收触摸的 UIKit 透明层，不再依赖可能被 Readium 分栏位移的 DOM 矩形层。原生长按回调与点按翻译之间设有单调时间门，不会被松手后的尾随点按覆盖；如果某版 WebKit 没有回调原生选区，非阻断的 UIKit 长按观察器会只读按点处的 ruby 基文并降级高亮。跨多组 ruby、逆向拖选、换行、横排和竖排都使用同一套基文节点规则，注音不会进入翻译。竖排坐标会补偿 Readium 以负 `contentOffset` 表达的安全区位移，翻译覆盖层因此能使用真实汉字位置智能避让。
- 译文卡片可直接收藏；原文、译文、语言对和书籍位置保存到本机 SwiftData，可在“学习”页统一搜索或删除。
- 译文卡片的更多操作可请求“AI 句子结构分析”。App 重点分析句子主干、成分、从句/修饰关系、英语时态与语态、日语助词与活用等语法点；只发送当前句段和经过长度限制的邻近上下文，沿用用户已配置的 AI 大模型或 AI 代理。分析有独立缓存、输出校验和超时保护，不会修改正文。
- 对在屏幕或 PDF 页边界被截断的句段，可选择“扩展跨页句段”。原选区上下文不足时，EPUB 会按需读取当前 Readium 章节中的基文节点并排除 ruby 注音；PDF 使用前一页、当前页和后一页文字层。在本机恢复可确认的完整句段后才发起一次翻译请求，避免重复计费；没有可靠上下文时不会臆造内容。
- 长按选中一个完整的中、英、日文词语并完成翻译后，可从译文卡片“更多”直接加入生词本；App 会优先补充真实词典的基本形、假名、词性、活用和例句，联网词典不可用时才保留本次译文作为降级释义。
- 翻译与 AI 句子结构分析完成时的触感反馈可在设置中独立关闭，不影响书签、标签切换等其他系统反馈。
- 翻译请求保留书籍 ID、Readium Locator 和选区位置；关闭覆盖层后清理临时选区但不改变阅读位置。
- 重复请求和请求乱序有请求 ID 保护，较早结果不会覆盖新结果。
- 翻译结果只显示在临时覆盖层中，不写入 EPUB 正文或改变原书排版。
- 删除确认以及本地副本清理。
- “书架”、“学习”和“设置”三标签主界面；学习页按翻译、生词本、练习与工具、历史排列，词典查询合并在词语翻译中，资源下载集中在设置。
- 设置中的“操作指南”覆盖导入途径、只读打开、点句/点段、日文引号选区、主题与选区配色、全书排版同步、PDF/OCR、学习功能、备份恢复，以及 Apple 系统翻译、AI 大模型和 AI 代理的配置。
- 参考微信读书沉浸式交互原则的书架与阅读控制：正文优先、控件按需出现，支持最近查看、分类筛选以及按最近、书名、作者排序；不复制第三方品牌资源。
- 浅色、护眼、冷灰和深色阅读主题使用各自适配的临时选区填充；自定义背景可单独选择选区颜色，低对比组合会自动校正以保持可见。EPUB、PDF 文字层和 OCR 共用该视觉规则。
- 翻译的词语模式会为日语/英语自动补充词典形、读音、词性、释义和例句，并写入本机历史。
- 句子译成日文时，使用本机日语分词为汉字添加假名注音，不额外请求在线服务。
- 日语查词结果包含基本形、假名、词性、中文释义、常见活用说明和例句；配置 AI 后可继续请求带原句语境的深度语法解析，结果保存在本机词条中，避免重复消耗。
- 复制、收藏与取消收藏；语音相关操作在当前版本暂时隐藏。
- SwiftData 查词历史、重复词条合并、查询次数和最近查询时间。
- 生词本与历史搜索、单条删除，以及“清空历史但保留收藏”的数据规则。
- 覆盖重复查询、收藏保留和孤立记录清理的离线单元测试。
- 覆盖翻译缓存、Unicode 归一化、语言识别和文本长度限制的离线单元测试。
- 生词与译文收藏可导出 CSV、Markdown 或 Anki TSV；查词可选择仅查询，或查询后直接加入生词本。

词语翻译中的词典详情优先查询内置中日词典与已安装的英语扩展包，未命中时沿用中文维基词典 MediaWiki API 等既有后备服务。联网查询只发送用户输入的单词，可自动还原常见日语和英语词形；联网词典失败时可打开本机已安装的 iOS 系统词典。Mock 仅供无网络自动化测试使用。1.5.0 起，关闭轻点翻译后短按 EPUB 正文词语即可直接查词并写入学习记录（两端）；命中准确度、ruby 与竖排仍待设备正式验收，降级方案仍是阅读中长按翻译并加入生词本，或使用“学习 → 翻译 → 词语”。

默认的 Apple 阅读内翻译不需要 API Key。首次使用某个语言方向时，iOS 可能要求联网下载语言包；完成后可离线使用。个人使用时，也可在“设置 → AI 大模型”添加供应商并粘贴自己的 Key，由 App 直接调用该服务商；官方地址和常用模型自动填写，并提供只发送固定短句的连接测试。不同服务商的 Key 分开保存在本机（iOS 钥匙串、Android 加密存储），不写入书籍、日志或安装包。公开分发或共享密钥时仍建议用“AI 代理”接自建 HTTPS 后端，让服务商 Key 只留在服务器上。单次翻译上限为 2,000 个字符。

## 阅读与翻译

1. 在书架点击封面进入阅读器；再次打开会恢复上次位置。
2. 在设置中选择“句子”或“段落”后，点击正文直接翻译所在句或所在段。默认开启“轻点翻译时禁用点按翻页”，此时用滑动或底部按钮翻页；关闭轻点模式、使用长按框选时，左右边缘点按翻页会恢复。也可单独关闭该保护开关，让轻点翻译与边缘点按翻页并用。
3. 长按单词会智能补全，长按句中多个词会优先补全句子；随后拖动系统选区手柄即进入精确模式，严格翻译最终框选内容。
4. 如系统提示下载语言包，请确认下载；译文默认在选区附近自动避让，拖动卡片顶部的短横条可手动移动，也可点星标收藏。
5. 顶部导航按钮集中打开目录、全文搜索和书签；字体、字号、背景、间距、日文排版和翻译接入均从齿轮“阅读与翻译”设置中调整。

PDF 在 iPhone 上使用单页阅读，在 iPad/横屏由 Readium 自动适配单页或双页。开启点句翻译后，轻点带文字层的句子会直接提取并翻译；点按容差固定为屏幕 16pt 并按当前缩放/旋转换算为 PDF 页坐标。双栏论文可在阅读设置中按书开启“论文双栏模式”：文字层与 OCR 的自动点句/点段只在点击的左栏或右栏组装，横跨整页的标题、摘要和图注会退回普通识别。该开关不改变 PDFKit 原生长按及手柄选区。原生长按选区设有手势门，松手后的尾随 tap 不会清除选区；即使 Readium 的选区回调短暂缺失，翻译菜单也会读取 PDFKit 当前选区。没有可用文字层的扫描页会在本机用 Vision 按需 OCR，OCR 长按时间为 0.30 秒，识别结果按页缓存，并只把命中的句子交给当前翻译服务。文字层高亮保留 `PDFSelection`，OCR 高亮保留页内归一化框，缩放、滚动和旋转时统一用 PDFKit 官方坐标转换重算，不会漂移。OCR 断句会结合行距、段首缩进、分栏和竖排几何关系；日文优先保留汉字本文，不把小号假名注音当作正文。低清、倾斜、手写体或复杂多栏扫描件可能影响 OCR 与阅读顺序。支持的 Word 格式为 `.docx`；旧版 `.doc` 不会在 App 内解析。

### AI 大模型配置

1. 打开“设置 → AI 大模型”，点“添加供应商”。Claude、ChatGPT、DeepSeek 排在最前，其后是通义千问、豆包、Kimi、智谱、MiniMax、Gemini；列表里没有的服务用“自定义”添加。
2. 粘贴在该平台创建的 API Key，勾选要用的模型。官方请求地址和常用模型已经填好，也可以点“获取可用模型”，从账户返回的列表里选。
3. 点“测试连接”，通过后点“添加”。测试只发送固定短句，不发送书籍内容。
4. 在“设置 → 翻译与 AI”把翻译服务选为“AI 大模型”，或在“设置 → AI 大模型”点“用它翻译”。之后阅读中轻点句子或长按框选即可调用；以后用“换模型”在已添加的供应商和模型之间切换。
5. 每个模型可单独设置接口格式（OpenAI 兼容、OpenAI Responses、Claude 兼容；Gemini 原生只保留给已经在用它的模型）和思考强度（自动、关闭、低、中、高）。

AI 大模型会把本次选中的文字、必要上下文和语言方向直接发送给所选服务商，并可能产生费用。App 不把 API Key 写入工程或安装包，但个人设备上的客户端密钥仍应视为可撤销凭据；建议设置平台用量上限并定期轮换。

**AI 套餐（2.0.0 起）**：“添加供应商”顶部切到“套餐”。

- **ChatGPT 套餐（实验）**：点“Continue with ChatGPT”，在 OpenAI 的页面登录后，翻译和语法解释走该 ChatGPT 账号的订阅额度，“设置 → AI 大模型”里出现“ChatGPT 套餐”一行，可以换模型、刷新模型列表、查看用量或退出登录。额度用完时请求停下并提示去 chatgpt.com 查看用量，不自动重试、不改用别的服务。登录凭据只存本机，不进备份，换设备或从备份恢复后要重新登录。协议细节（授权地址、PKCE、回环回调、刷新与撤销）见 [架构说明](ARCHITECTURE.md) 的「2.0.0 AI 套餐与「纸墨」界面」。测试只用 Mock，没有用真实账号登录过；OpenAI 还没公开说明移动端的这种登录，所以标为实验。
- **Claude 套餐额度**：只是说明页。Claude Max、Ultra 每月附带的 API 额度要在 Claude 控制台建 API Key，按普通 Claude 供应商添加。
- 编程套餐（Coding Plan、Token Plan 等）的条款只允许在编程工具里用，不接入，页面底部有一行说明。

### AI 代理协议

“AI 代理”是你自己部署的 HTTPS 中转服务：App 只把请求发给它，由它在服务端保存供应商 Key 并转发给任意 AI 供应商。在“设置 → 翻译与 AI”选择“AI 代理”后填写完整的 `https://` 地址，模型名称和代理访问凭据都可以不填。仓库里没有现成的代理服务端。

翻译和 AI 解析（句子结构分析、阅读透镜、语境查词）都用 `POST` 把 JSON 发到这个地址，iOS 和 Android 发的是同样的请求。已打出的 1.6.0 (68) 及更早的 Android 安装包还是旧格式：两类请求只用 `operation` 字段区分，不带 `context`，也不带下面两个 `X-Jerreader-` 请求头。

翻译请求：

```json
{
  "text": "选中的原文，最多 2,000 字符",
  "context": "可选：邻近上下文",
  "sourceLanguage": "ja",
  "targetLanguage": "zh-Hans",
  "model": "可选：设置里填的模型名称",
  "prompt": "由翻译提示词生成的指令"
}
```

解析请求：

```json
{
  "task": "explain",
  "analysisMode": "grammar",
  "text": "要解析的句段",
  "context": "可选：上下文，语境查词时附词典候选资料",
  "sourceLanguage": "ja",
  "responseLanguage": "zh-Hans",
  "model": "可选",
  "prompt": "由解析提示词生成的指令"
}
```

`analysisMode` 取 `comprehension`、`context_meaning`、`reference`、`grammar` 之一，对应阅读透镜的四种问法；普通的句子结构分析和语境查词是 `grammar`。代理看有没有 `"task": "explain"` 就能区分两类请求。

语言代码是 `zh-Hans`、`en`、`ja`。可选字段没有值时直接省略：Android 的翻译请求目前不带 `context`，iOS 解析请求的 `sourceLanguage` 也可能省略。`prompt` 已含完整指令，转给上游模型时可直接作系统提示词，`text` 和 `context` 作用户内容。

两端都带这些请求头：

- `X-Jerreader-Translation-Protocol: 1`。
- 填了代理访问凭据时，带 `Authorization: Bearer <凭据>`。
- 翻译请求另带 `X-Jerreader-Idempotency-Key`。同样的文字、上下文、语言方向和代理设置（地址、模型、提示词）得到同一个值，自动重试时也不变。代理应在短时间窗口内复用同一键处理中或已完成的结果，避免重复调用上游 AI。

成功时返回 2xx 和 JSON。翻译结果读 `translatedText`，没有再读 `translation`；解析结果依次读 `explanation`、`answer`、`translatedText`、`translation`。两类请求都回 `{"translatedText":"..."}` 最省事。

App 自己的处理还有两处不一样，不影响代理怎么写：

| | iOS | Android |
|---|---|---|
| 等待时间 | 翻译 30 秒，解析 60 秒 | 连接 20 秒，读取 45 秒 |
| 出错时 | 401/403 显示鉴权失败，400、404、405、415、422 按配置错误处理，其他状态码按暂时不可用处理 | 显示响应里的 `error`（字符串，或对象里的 `message`），没有时显示 HTTP 状态码 |

## 打开与运行

1. 安装带 iOS 18 SDK 的完整 Xcode（Xcode 16 或更高版本）。
2. 用 Xcode 打开 `Jerreader.xcodeproj`。
3. 等待 Swift Package Manager 获取项目锁定的 Readium 提交 `3d8bcdc`。
4. 本机默认只做 generic iOS device 未签名构建，不启动模拟器。无论手动构建还是交给 AI 编程助手，都要从仓库根目录使用保护脚本：

```sh
scripts/safe_xcodebuild.sh build
```

若当前 Developer 目录只有 Command Line Tools，先把 `DEVELOPER_DIR` 指向完整 Xcode 的 `Contents/Developer`。构建失败后先定位错误，不连续重跑。模拟器测试需要用户在当前任务明确授权；授权后再按 [构建保护规则](../AGENTS.md) 设置单一设备 UDID，通过保护脚本的 `test` 或 `ui-test` 模式执行。

日常先运行 `scripts/safe_xcodebuild.sh doctor` 与 `host-test`，检查资源并完成五组无需模拟器的生产 Swift 回归。保护入口默认单 job、运行中监测内存与磁盘（负载和温控只记录），模拟器编译与运行分阶段执行，详见 [iOS 低负载验证](IOS_SAFE_TESTING.md)。主机回归及 generic 构建不等同于 iOS 单元/UI 测试通过。

2026-11-13 起系统负载和温控降频只记录，不再排队或中止任务（此前是 150 的负载排队门槛）；其他构建运行时仍然等待，再逐个执行。iOS 与 Android 打包共用排队锁，编译固定单 job / 单 worker；Android 入口为 `scripts/safe_android_build.sh`。内存、磁盘、显示异常及模拟器授权保护继续生效。打 IPA 可以用 `scripts/background_build.py submit` 放到登录会话之外运行，系统把会话踢回登录界面时任务不会中断。

Android 构建和打包见 [构建与交付](android/BUILD_AND_PACKAGE.md)。1.7.0 的改动、实测结果和没验证的部分见 [1.7.0 维护记录](RELEASE_1.7.0_2026-11-17.md)，只有 Android 的 1.7.1 见 [1.7.1 维护记录](RELEASE_1.7.1_2026-11-18.md)，1.4.0 的界面验收见 [1.4.0 界面验收](UI_PARITY_1.4.0.md)；新能力方案见 [新功能开发方向](FEATURE_DIRECTIONS.md)。
